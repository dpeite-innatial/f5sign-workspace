# Perf Smoke Frontend

Frontend performance smoke test. Only if tag `critical-path`. Not a hard gate — WARN.

## Invocation

```
/perf-smoke-frontend T{id}
```

## Inputs

- `var/task-runner/T{id}/changes.diff`
- `var/task-runner/T{id}/context-digest.md`
- Task `.md`
- Bundle snapshot of `main` (pre-generated by task-runner)

Default thresholds (overridable via `.md` in the "Detalle tecnico" subsection):
- Bundle delta: `<+10%` pass, `+10-25%` warn, `>+25%` high warn
- Lighthouse Performance: `≥80` pass, `60-80` warn, `<60` high warn
- LCP: `<2.5s` pass, `2.5-4s` warn, `>4s` high warn
- CLS: `<0.1` pass, `0.1-0.25` warn, `>0.25` high warn

## Outputs

- `var/task-runner/T{id}/perf-smoke-frontend.report.md`
- `var/task-runner/T{id}/perf-metrics-frontend.json`
- `var/task-runner/T{id}/bundle-analysis.html` (if vite analyze runs)
- `var/task-runner/T{id}/lighthouse-report.json` (if lighthouse runs)
- JSON: `{"status":"pass|warn|fail","summary":"...","issues":[...],"metrics":{"bundleDelta":0.12,"lighthouse":{...}}}`

`fail` ONLY if the skill could not run (broken environment).

## Execution

### Step 1 — Determine what to measure

Based on context-digest and diff:
- Modified routes/pages → candidates for Lighthouse
- New heavy components → candidates for bundle analysis
- If nothing is measurable → `status: warn, summary: "tag critical-path but nothing measurable"`, add `tagMismatches: ["critical-path"]`

### Step 2 — Bundle size

```bash
npm run build
```

If the project has `rollup-plugin-visualizer` or `vite-bundle-analyzer`:
```bash
# Generates HTML analysis
npm run build -- --analyze
# Or, depending on the setup
npx vite-bundle-visualizer
```

- Calculate the current bundle size (dist/ or equivalent)
- Compare against the `main` snapshot (provided by task-runner)
- Delta:
  - `<+10%` → pass
  - `+10-25%` → WARN
  - `>+25%` → high WARN

Detect new heavy imports (libraries >50KB added):
- Parse the `package.json` diff
- If there's a new dependency: estimate its size (via `bundlephobia` if available online, or from the bundle analysis)
- If > 50KB gzipped → WARN "heavy dependency {name} ({KB})"

### Step 3 — Lighthouse CI

Requires:
- Preview server running (`npm run preview` or `npm run dev`)
- Backend accessible (can be mock or real)

```bash
npx lighthouse {route-URL} --output=json --output-path=var/task-runner/T{id}/lighthouse-report.json --chrome-flags="--headless"
```

For each affected route, run Lighthouse and extract:
- Performance score (0-100)
- Accessibility score
- Best Practices score
- SEO score
- Core Web Vitals metrics: LCP, FID (or TBT), CLS

Compare against thresholds:
- Performance:
  - `≥80` → pass
  - `60-80` → WARN
  - `<60` → high WARN
- Accessibility: `<90` → WARN (if the task is critical, consider FAIL — this is primarily handled by a11y-check)
- LCP / CLS: per the threshold table

### Step 4 — Core Web Vitals

Included in Lighthouse. Report explicitly:
- **LCP** (Largest Contentful Paint): target <2.5s
- **FID / TBT** (First Input Delay / Total Blocking Time): target <100ms / <200ms
- **CLS** (Cumulative Layout Shift): target <0.1

### Step 5 — Render analysis (optional)

If available: run Playwright with captured Vue DevTools output. Detect components with >5 re-renders during a simple interaction. Report as WARN "component {X} re-renders excessively".

### Step 6 — Fallback

If the Lighthouse CLI isn't installed, or vite build isn't available, or the preview server doesn't start:
- `status: warn`, clear summary of what's missing
- Skip the corresponding measurement but attempt the rest

Never block due to missing infra in dev.

## Severity

Everything WARN (or FAIL only if the skill could not run). The debt is left in `notes.md` for `task-close`.

## Report

```markdown
# perf-smoke-frontend — T{id}

**Status:** {PASS|WARN}
**Issues:** {N} warnings ({high}/{medium})

## Metrics

### Bundle
- main size: 342 KB gzipped → 358 KB gzipped
- Delta: +4.7% ✓
- New dependencies: none

### Lighthouse (route /dashboard)
- Performance: 87 ✓
- Accessibility: 96 ✓
- Best Practices: 92 ✓
- SEO: 88 ✓

### Core Web Vitals
- LCP: 1.8s ✓
- FID (TBT): 50ms ✓
- CLS: 0.05 ✓

## Warnings
- [bundle-heavy-dep] `@tiptap/core` added (~80KB gzipped); consider lazy-loading
- [lighthouse-seo] Missing meta description on new page /signer/uuid
```

## Return JSON

```json
{"status":"warn","summary":"1 new heavy dependency + SEO could be improved","issues":[{"severity":"warn","category":"bundle-heavy-dep","message":"@tiptap/core ~80KB gzipped"}],"metrics":{"bundleDelta":0.047,"lighthouse":{"performance":87,"accessibility":96,"lcp":1800,"cls":0.05}}}
```

## Interaction with the loop

Never triggers an automatic retry. If supervised and there's a high WARN, task-runner asks whether to iterate or leave debt.

## What it does NOT do

- Not load testing (concurrency, spikes)
- Does not analyze the performance of third-party code (node_modules)
- Does not do runtime JS profiling with flamegraphs
- Does not optimize — only detects
