### F1 (95, check 1/3) — `RouteAuthnDeclarationTest` goes red on this commit
`tests/F5Sign/Foundation/Integration/RouteAuthnDeclarationTest.php::each_recipient_credential_names_exactly_the_routes_it_admits`
asserts the `SESSION_CREDENTIAL` route set is exactly
`['signing.commit', 'signing.decline', 'signing.document', 'signing.session_read']`. It collects every `/api/`
route's `_authn`, so `evidence_audit.download_session_receipt` now joins that set and the `assertSame` fails. It is
an Integration test, and the report says only the fast tiers plus the filtered classes ran, so the red was not seen.
**Fix:** add `'evidence_audit.download_session_receipt'` to that expected list (sorted: it sorts first) and extend
the assertion message: "…the read-model, the bytes, the two acts — signing and declining (ADR-0070 §2.4, BL-142) —
and the recipient's own receipt (ADR-0086 §2.6, declared in `evidence_audit.php`), and nothing else". The
under-prefix completeness check already holds (the path is under `/api/v1/signing/`). Re-read that test's docblock
for a now-false count. Run the class on the lane.

### F2 (60, tenant — reported without cut) — the new credential route has no cross-tenant case
`tests/F5Sign/Session/Integration/SessionCredentialTenantScopeTest.php` states P-RLS-6, "a request admitted by a
session credential reads only its own tenant's rows, **on every route the credential admits**", and its docblock
names the hazard exactly: a tenant-A credential carrying tenant B's `eid`/`rid`, on a connection carrying B's GUC.
The new route reads Envelope's recipient context by direct DBAL, the `issued_receipt` registry and
`session.signing_session` — all narrowed only by the listener's GUC — and no case covers it. The listener applies
scope uniformly, so no leak is expected, but the property is claimed for a route that is not in the harness.
**Fix:** add a case to `SessionCredentialTenantScopeTest` for `GET /api/v1/signing/session/receipt`: tenant B has a
receipt recorded for its recipient (registry row + custody bytes); a credential with `tid` = A and B's `eid`/`rid`,
sent with the connection pre-scoped to B as the class's other cases do → 404; and B's own credential → 200 (the
discriminating half). If the orchestrator prefers to defer it, record the gap in the task's open follow-ups instead.

## Ruling on the implementer's concern (unsent guard, two guards in series)
Not a defect. `RecipientEnvelopeContextView::withholdsDocumentFromRecipient()` returns `true` for `sentAt === null`
by contract ("never sent; or closed, and…"), so no fixture can make the explicit `sentAt === null` guard the only
refuser: it is unreachable-by-design defence in depth, exactly as in the reference
`SigningDocumentReader` (which documents its own copy as "Defence in depth rather than the load-bearing guard").
The behaviour (unsent → null, no store or session read) is pinned by `an_unsent_envelope_serves_no_receipt`
whichever guard fires; the literal is pinned by the census count. The commit message states this honestly.
Optional (low): add one clause to the handler's comment saying the withholding below also refuses an unsent
envelope and the census counts this guard, so nobody deletes it as dead.
