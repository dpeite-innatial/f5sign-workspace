## Question
`GetSessionReceiptHandler` is a new caller of `EnvelopeQueryInterface::getContextForRecipient()`, and
`SigningReadersRefuseUnsentEnvelopeTest` censuses every such caller on three axes and fails on an unclassified one:
1. **Unsent (ADR-0058)**: `CLASSIFIED` row + the literal guard `sentAt === null` in the class (a count, one per
   crossing). The handler refuses an unsent envelope already, through `withholdsDocumentFromRecipient()`, but the
   census counts the literal only. Proposal: add `if ($context->sentAt === null) { return null; }` before the
   retirement check, plus a handler case `->neverSent()` → null.
2. **Terminal (ADR-0059)**: `TERMINAL_CLASSIFIED` row. Proposal: `REFUSES`, pointing at
   `a_retired_credential_and_a_withheld_recipient_are_not_found`; the handler already carries the accepted spelling
   `if ($context->withholdsDocumentFromRecipient())`.
3. **Step (ADR-0066)**: `STEP_CLASSIFIED` row — REFUSES (add `if ($context->stepHoldsTheRecipientBack())`, as
   `SigningDocumentReader` does) or EXEMPT (a dormant recipient cannot have acted, so has no receipt and no
   COMPLETED/DECLINED session, and gets 404 anyway — but EXEMPT needs a named case proving it). The slice lists
   neither.

This touches a file outside the slice's Files (the Session census test) and adds handler guards the slice's
step order does not list. Which dispositions, and may I edit that census file?
