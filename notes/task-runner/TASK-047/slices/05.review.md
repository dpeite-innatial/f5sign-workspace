## Rulings on the implementer's concerns
1. **Document name stated as `Stated(name, ROW)`, including the id fallback.** The trail's `documents()` states the
   same fallback (`$names[$documentId] ?? $documentId`) as a bare string in `DocumentRecord`, with no source.
   The receipt's `ReceiptDocument::$name` is a `Statement` (slice 02), so it has to carry a source. In the case
   that actually happens, ROW is the right source:
   - `Document::$displayName` has no mutator.
   - `Envelope` Domain has no document removal.
   - An assignment references a document of the envelope.

   So the fallback is defensive and unreachable today. If it ever fires, ROW would misattribute the id as a
   recorded name. The fix belongs to slice 04's type, so it is a follow-up, not this slice: the
   `ReceiptDocumentSource::$name` becomes `Option<string>`, and the assembler states `None` as
   `Unstated(SOURCE_UNAVAILABLE)`. Low confidence (35), below.
2. **"Expected and no source" is untested.** Real gap, not a correctness defect. The behaviour matches the slice.
   The branch is invisible to coverage because PHP evaluates `mapOr`'s default eagerly, so the line is covered while
   the case is not. The same applies to `bytes FAILS`/`NOT_EVALUATED` and to the certificate `Unstated` fallback.
   Low confidence (65), below: worth a cheap test, but not a fix-loop item.
3. **Envelope id from the boundary row's `streamId`.** Correct. The settled read is scoped to
   `trigger->envelopeId`, so every row's `streamId` is that envelope. It is the "derived from the stream prefix"
   reading. The test pins it lowercase, and the chain is folded over the same id. Approve.
4. **TrailAssembler reorder.** I verified it independently: a sorted-line diff of the before/after file, with
   `private`/`public static function` normalised, shows only these added lines:
   - the 8 "Shared with…" lines;
   - the `*` separators;
   - two new `/** … */` pairs, for the readings that had no docblock.

   No body changed. Move-only, so AC-15 holds.

## Low confidence
- (35, check 4) `ReceiptAssembler::document()`: `new Stated($document->name, Source::ROW)` also stamps ROW on the
  gatherer's id fallback. Fix, if wanted: in `ReceiptSourcesGatherer`, pass `Options::fromNullable($names[$documentId] ?? null)`
  as `ReceiptDocumentSource::$name: Option<string>`. In `ReceiptAssembler::document()`, state it as
  `->mapOr(new Unstated(UnstatedReason::SOURCE_UNAVAILABLE), fn($n) => new Stated($n, Source::ROW))`. This needs a
  plan amendment, because it touches slice 04's file.
- (65, check 1/rule 4) Untested branches in `ReceiptAssembler::document()`/`revision()`:
  - revision expected with no source → `Some(Unstated(SOURCE_UNAVAILABLE))`;
  - `digests` None → `NOT_EVALUATED`;
  - prefix or whole mismatch → `FAILS`;
  - no read-back signature at the artifact's size → certificate `Unstated(SOURCE_UNAVAILABLE)`.

  Suggested fix: add a builder switch `withoutRevisionSource()` and one test asserting
  `Some(new Unstated(UnstatedReason::SOURCE_UNAVAILABLE))` for a sequential signer. Add `withoutDigests()` and
  `withReadBack([])` cases for the other two.
