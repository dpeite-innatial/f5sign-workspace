# Slice 08 — One recipient's receipt is issued once, when its fact makes it true

| Tier | critical |
| Covers | AC-1, AC-2a, AC-2c, AC-9d (issuance half), AC-10a, AC-11, AC-14a–AC-14e |
| Depends on | slice 04, slice 05, slice 06, slice 07 |

## Goal
`IssueReceipt` (command, `OwnsUnitOfWork`) and `IssueReceiptUseCase` mirror the trail's issuance for one recipient:
registry check, the mode and role checks, gather, assemble, render, seal, then `writeAlongside` with the claim.
`ReceiptEligibility` holds the two exhaustive rules.

## Why
"`SESSION_COMPLETED` — a signer or an approver under `SINGLE_SEAL`, and nothing under `SEQUENTIAL_PADES`. The event
carries no mode and a reactor reads nothing (ADR-0002), so the mode check sits in the use case, which reads the
envelope context, as `SignForRecipientUseCase` does" (§3 #2). "Signers, approvers and decliners get one. Nobody
else." (§1)

## The steps (decided here)
1. `own(fn => receipts->exists(id))` → true: return. 2. `getEnvelopeContext(envelopeId,
SystemActorId::boundedContext('EvidenceAudit'), clock->now())`; `EnvelopeNotFoundException` → `ReceiptNotIssued`
`SAME_RESULT`. 3. `!issuesOn(fact, context->signingMode)` → return. 4. The recipient's `RecipientView` in
`context->recipients`; none → `ReceiptNotIssued` `SAME_RESULT`. 5. `!receives(role)` → return. 6. renderer
`identity()` (render outlooks as the trail's). 7. `gather(trigger, context, recipient, identity)`:
`ActNotSettledYet` → `MAY_SUCCEED`; `ActNotRecorded`, `ReceiptEnvelopeUnreadable` → `SAME_RESULT`; any document whose
read-back is `Err(ReadBackServiceUnavailable)` → `MAY_SUCCEED`. 8. assemble, render (empty → `emptyPdf`), seal as
`justificante-<envelope>-<recipient>.pdf` (seal outlooks as the trail's). 9. `CustodyId::generate()`, `open(…, context->tenantId,
CustodySubject::fromString(envelopeId), Obligation::fromTransient())`. 10. `IssuedReceipt::issue(id, tenant, refs,
custody, fact, boundary position, generation at)`; `writeAlongside(…, claim → Err(ReceiptClaimedElsewhere))`, a lost
claim whose recovery reached a known state ends quietly; other failures → `ReceiptNotIssued` (registration outlook).

## Prose to write
Use case docblock: the trail's, rewritten for one recipient — steps 1–10 above in prose; Invariants ("a row means a
receipt with its bytes"; idempotent through the derived subject; every refusal throws); Concurrency and Limits as the
trail's; plus: "**Two rules decide whether there is a receipt at all, before anything is read from the log.** The
fact must make the receipt true under the envelope's mode (`ReceiptEligibility::issuesOn()`: under
`SEQUENTIAL_PADES` the commit is admitted before a worker applies the signature, BL-462), and the role must be one
that acts (`ReceiptEligibility::receives()`). Both answer by returning, not by refusing: a fact that issues nothing
is not a failure. Never claim the registry row before the bytes are written (ADR-0076 §7.1)."
`ReceiptEligibility`: "Who gets a receipt, and on which fact (ADR-0086 §2.2). Exhaustive with no default, so a role
or a fact added later must choose (authoring rule 5)."
