## Rulings on the implementer's concerns

- **`ReceiptBoundary::$eventType` as `string`.** This is not a defect in this slice. The *Shape* leaves the type open
  and types the sibling `ReceiptFact::$eventType` as `string`. The enum's stated job is to spell the trigger types for
  the code that dispatches on them. If the use-case slice builds the boundary from a `ReceiptBoundaryFact`, it can pass
  `->value`, or retype the field there.
- **Signer fixture `closed_before` at 7, after the act at 6.** This contradicts the `$closedBefore` docblock ("at or
  before the act"), but `Receipt::of` does not enforce that, and the fixture's docblock says it is a shape for the
  encoder. It is harmless for the key-list test.
- **Key-list test green against the empty placeholder.** Sabotage 1 turns it red with the list in place, so it can
  fail. I also checked the literal by hand against the *Shape* and against each model class's properties, so it is not
  only a snapshot of whatever the encoder emitted.
