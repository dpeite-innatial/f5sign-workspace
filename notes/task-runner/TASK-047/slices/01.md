# Slice 01 — The settled read can stop at the first row of a type and a subject

| Tier | critical |
| Covers | AC-9 (AC-9a, AC-9b, AC-9c, AC-9d) |
| Depends on | none |

## Goal
`EventStreamReader::readSettledToSubject()` returns a stream's rows up to and including the lowest position
whose type is in a list and whose `subject_id` is a given subject, with the type read's wait, tenant rule and
refusals, through a new overload of `platform.read_settled_stream` (ADR-0086 §2.1, amending ADR-0071 §2.3).

## Why
"`EventStreamReader` gains a read that stops at the lowest position whose type is in a list **and** whose
`subject_id` is a given subject, with the same settledness, tenant rules and refusals as the type boundary
(ADR-0086 §2.1). A relayed fact carries no log position, but its `subject()` names the act." (TASK-047 §3 #1)

## Prose to write
- Port method docblock: "Returns the stream's rows up to and including its first act of one subject: the
  lowest position whose event type is one of `$boundaryEventTypes` and whose subject is `$boundarySubjectId`,
  once no writer of the stream is still open (ADR-0086 §2.1). Everything else is as `readSettled()`: the
  caller's tenant's rows only, position order, the same wait, the same two refusals and the same
  `\LogicException`. A row of a boundary type with another subject is an ordinary row: it neither ends nor
  shortens the read. A second row of the same type and subject above the first does not move the boundary."
  Same `@param`/`@return`/`**Throws**` shape as `readSettled()`; `$boundarySubjectId` is a canonical UUID.
- Interface class docblock: append "A caller may also name the subject of its boundary fact
  (`readSettledToSubject()`), because one stream can hold one fact of a type per act."
- Migration class docblock: "Lets the application read one stream up to the first fact of a type **about one
  subject** (ADR-0086 §2.1, amending ADR-0071 §2.3). `platform.read_settled_stream(stream, boundary_types,
  boundary_subject, wait_ms)` is an overload of the function `Version20260922000002` created, and that
  migration's docblock holds for it word for word — the wait on the stream lock, the outcomes, what raises, and
  the security notes — except that the boundary is the lowest position whose type is in the list **and** whose
  `subject_id` is `boundary_subject`. An envelope's stream holds one `RECIPIENT_SIGNED` per recipient, so a
  type alone cannot name one recipient's act; the relay carries no log position, and a fact's subject names
  its act. A NULL subject is `invalid_parameter_value`. The overload is owned by `f5sign_log_reader`, is
  executable by `f5sign_app` only, and ends its `search_path` with `pg_temp`."

## Claims you may NOT copy
- "the caller names the ones that end its stream" as the whole story: here a type of the list may appear many
  times before the boundary.
