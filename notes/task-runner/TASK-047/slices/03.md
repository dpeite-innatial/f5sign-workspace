# Slice 03 — Session answers one recipient's session status through its contract

| Tier | critical |
| Covers | AC-8 (support: AC-8b, AC-8c read "has acted" from Session) |
| Depends on | none |

## Goal
`Session/Contract/Query/SessionStatusReader::forRecipient(EnvelopeRef, RecipientRef): Option<SessionStatus>`
answers the status of the one session a recipient has on an envelope, under the caller's tenant, realized by
`DbalSessionStatusReader` over `session.signing_session` (ADR-0086 §2.6, §6 "Realized in").

## Why
"Whether that session has acted (§4 #5) is Session's to answer, and its contract exposes no such read today …
So Session gains one port in `Session/Contract/Query` that returns one session's `SessionStatus` …, keyed by
envelope and recipient (the credential carries those, not a session id; a recipient has at most one session),
scoped to the caller's tenant, with its refusals as values." (TASK-047 §3 #5)

## Decided here
- The one refusal is the absence: `None` when the caller's tenant has no session for that (envelope, recipient),
  which also covers an unknown envelope and another tenant's — indistinguishable, as the siblings state. A
  `Result` would carry no second variant. A database failure or a missing tenant scope raises the DBAL exception.
- Read: `SELECT status FROM session.signing_session WHERE envelope_id = :envelope AND recipient_id = :recipient`;
  `SessionStatus::from($status)` (a `\ValueError` on a value Session never writes propagates). No lock, no aggregate.

## Prose to write
- Port: "Reads the status of the one signing session a recipient has on an envelope, for a context other than
  Session: Evidence & Audit's session route asks whether the recipient's own act closed it (ADR-0086 §2.6). The
  sibling of `ActEvidenceReader` and `SignatureImageReader`, with the same scope: the caller's tenant. Session
  holds at most one session per recipient of an envelope (`signing_session_recipient_uniq`), so the pair is the
  key; the session credential carries the pair and no session id. `None` means the caller's tenant has no such
  session: an unknown envelope, another tenant's and a recipient who never opened one read alike. **Throws** the
  DBAL exception when the database fails or the tenant scope is missing."
- Adapter: "Realizes `SessionStatusReader` against `session.signing_session`, under the caller's tenant scope. A
  read, not a load: no row lock, no aggregate, like `DbalSignatureImageReader`."
