## Warnings
- [missing-nosniff] src/F5Sign/EvidenceAudit/UI/Http/DownloadSessionReceiptController.php (response build after the `$content === null` check) and DownloadRecipientReceiptController.php (same block): both new PDF downloads send `Content-Type` (server constant `ReceiptBytes::CONTENT_TYPE = application/pdf`, not client-supplied) and `Content-Disposition: attachment` via `HeaderUtils::makeDisposition`, but no `X-Content-Type-Options: nosniff`. `rg nosniff src config` finds nothing, so this is the known repo-wide gap; the diff adds two more surfaces to it and no test asserts the header (tests assert only Content-Type and Content-Disposition: SessionReceiptHttpTest.php:106-109, RecipientReceiptHttpTest.php:82-85). Low practical risk because the type is fixed and the body is Typst-produced.
- [pii-at-rest] The sealed receipt PDF held in custody (and its attached JSON) carries the recipient's name, IP, User-Agent, Accept-Language and asserted identity in the clear (ReceiptPersonal implements Pii; ReceiptJson::recipient). ADR-0033 is not enforced, so nothing encrypts it; same posture as the audit trail. The new table `evidence_audit.issued_receipt` (migration Version20261023100913) holds no PII (ids, custody id, boundary, timestamps), so no new plaintext PII column. No new event payload and no logging of PII were found: `IssuedReceipt` records no fact, and the controllers log only the exception on a detected substitution (ids, no PII).
- [duplicated-rule] src/F5Sign/EvidenceAudit/Application/Query/GetSessionReceiptHandler.php (the `$retiredAt` / `getTimestamp() <` block): re-implements the retirement comparison inline. `RecipientAuthContext::retires()` (Session/Application/Query/RecipientAuthContext.php:373) is the documented single home. Behaviour is equal today (the test at GetSessionReceiptHandlerTest.php:185-196 pins the boundary), but a future change to the rule in one place would silently diverge here and leave a retired credential able to download the receipt. Note also that this handler skips `recipientCouldPassTheGate()` that SigningDocumentReader asks; for an acting recipient the answer is true, so I found no hole, but the omission is not explained.
- [test-gap] Cross-tenant and rejection coverage for the SESSION_CREDENTIAL route is at handler level (retired credential, withheld recipient, unsent envelope, step not reached), not HTTP: SessionReceiptHttpTest covers unauthenticated, not-acted and another-recipient only. No HTTP-level test for a retired credential or a closed envelope. Machine route has a combined 404 test (RecipientReceiptHttpTest.php:119) for unknown, other tenant, other recipient; RLS isolation there runs on one connection under DAMA, so the tenant isolation actually comes from the policy plus the `IssuedReceiptId` derivation, which this test cannot separate.

## Checked and fine
- Auth seam: `evidence_audit.php` declares `Authn::MACHINE_KEY` on the recipient-receipt route and `Authn::SESSION_CREDENTIAL` on `/signing/session/receipt`; no fallback, no identity header read. Session route takes envelope and recipient only from verified credential claims (controller `claim()`), never from the path or query; a second recipient's receipt is unreachable by construction.
- Liveness (credential dies with its resource): the session handler asks `getContextForRecipient` (tenant from scope), refuses unsent envelopes, retired credentials (ADR-0060), closed envelopes withheld from the recipient (`withholdsDocumentFromRecipient`, ADR-0073 §2.15), and a step not yet reached; all four return null, so 404, with one answer. A recipient who signed keeps their receipt after a void by design (ADR-0086); that is a decision, not a hole. RECEIPT_NOT_READY (409) is only returned after those checks, so it does not disclose state to a retired or withheld credential.
- Machine route: `GetRecipientReceiptHandler` finds by the derived `IssuedReceiptId` under the tenant policy; unknown, foreign-tenant and not-yet-issued all map to one 404. Path ids pass through `AuditedEnvelopeRef/AuditedRecipientRef::fromString` (UUID validated, malformed -> 400, test at RecipientReceiptHttpTest.php:174). Filename is `justificante-<uuid>-<uuid>.pdf` from validated, lower-cased UUIDs, so no filename injection or traversal; ETag is the content sha256 with `Cache-Control: private`.
- SQL: every statement in `DbalIssuedReceiptRepository`, `DbalSessionStatusReader` and the two `DbalEventStreamReader` calls uses bound parameters; the only string concatenation is the constant `COLUMNS`. `DbalTenantsWithUnconservedReceipts` interpolates a class constant function name only.
- Migrations: `issued_receipt` has ENABLE + FORCE RLS, a USING/WITH CHECK policy on `current_tenant_id()` and the tenant-id trigger; `f5sign_app` gets SELECT, INSERT and a column-scoped UPDATE (conserved_*). Both SECURITY DEFINER functions set `search_path` with `pg_temp` last, are owned by the NOLOGIN role (`f5sign_log_reader`, `f5sign_evidence_audit_custodian`), `REVOKE EXECUTE ... FROM PUBLIC`, and `GRANT EXECUTE` only to `f5sign_app`. The custodian holds only `SELECT (tenant_id, conserved_at)` and a policy `TO` that role limited to `conserved_at IS NULL`. The settled-stream overload checks the tenant scope (`public.current_tenant_id()`), isolation level and parameters, and reads under the owner's tenant-scoped policy. The sentinel-tenant `set_config` is transaction-local and restored, same pattern as the existing funnels. Edit to Version20260922000002 is docblock only.
- Receipt content: one recipient only. Other parties appear only as a count and chain root (`chain.leaves`, `chain.root`), with envelope title and tenant name stated by design; the sender's identity is not included. Facts of the stream are folded to hashes, not emitted.
- Typst subprocess: `Process` with an argument array (no shell), empty environment (every inherited var set to false), 10 s timeout from config, job dir created `0o700` under a random 16-hex name, `--root` is the job dir, system and embedded fonts ignored, package paths inside the job dir, cleanup in `finally`. All data reaches Typst as JSON read with `json()`, never interpolated into markup; the template has no `eval`, `raw`, `link` or `import` (receipt.typ:13-14, 222 is `pdf.attach`). Template and Typst version are checked against the generation named by the receipt (`GenerationMismatch`) before rendering.
- Error mapping: `ReceiptNotReadyException` and `ReceiptUnavailableException` are `ConflictException`/`ProblemCoded`; messages carry only the caller's own ids and a fixed sentence; `substituted()` deliberately returns the same message as a missing custody, so storage detail does not leak.
- Dockerfile and `evidence_audit.yaml`: comment and parameter additions only (template path); no new binary, version or secret.
- No deserialization, eval or dynamic include in the diff.
